# ADR contract v1

Store ADRs as `peos/decisions/ADR-<sequence>-<slug>.md` with status `proposed`, `accepted`, `superseded`, or `rejected`.

Each ADR contains context and forces, technical current and target state, decision, alternatives, consequences, compatibility/migration, rollout/rollback, security/operability, validation, and links to related changes. The architect recommends; the named engineering owner accepts. Superseding an ADR creates a new ADR and cross-links both records.
